## What I did

1. Ran the current tree's five acceptance commands before any change. `typecheck` and `build`
   failed (exit 2) with `src/App.test.tsx(2,18): error TS2305: Module
   '"@testing-library/react"' has no exported member 'screen'`. `test` failed (exit 1) with a
   runtime error: `Cannot find package '@testing-library/dom'`. `lint` and `check:api` passed
   (exit 0).
2. Traced the type error to its cause: `@testing-library/react` re-exports `screen` from
   `@testing-library/dom`, a declared peer dependency of both `@testing-library/react` and
   `@testing-library/jest-dom` (`npm ls @testing-library/dom` showed it absent from
   `node_modules` despite being required). `legacy-peer-deps=true` in `.npmrc` had let `npm ci`
   silently skip installing it. `tsconfig.app.json` already includes `src` (which covers
   `App.test.tsx` and `src/test/setup.ts`), so test files were already part of the `typecheck`
   project — the previous session's "pre-existing type error" was a self-inflicted consequence of
   its own `.npmrc` change, not a real code defect.
3. Removed `legacy-peer-deps=true` from `.npmrc` and ran `npm ci`, which reproduced an `ERESOLVE`
   conflict: `openapi-typescript@7.13.0` requires `typescript@^5.x` as a peer, but the project
   installs `typescript@6.0.3`.
4. Checked `npm view openapi-typescript dist-tags` — `latest` is `7.13.0` (the installed version,
   still `^5.x` only); the only newer tag, `next`, is a `7.0.0-rc.1` prerelease. No stable release
   accepts TypeScript 6, so per the task's fallback I added a single `overrides` entry in
   `package.json` scoped to `openapi-typescript`'s `typescript` peer, pinned to the project's own
   TypeScript version via `$typescript`. `npm install` (to refresh the lock file) then `npm ci`
   and `npm ls` both exit 0 with no unmet peers.
5. Re-ran `typecheck`, `test`, `build`: all exit 0 with no code changes to `App.test.tsx` — the
   fix was entirely the peer-dependency resolution, confirming step 2's diagnosis.
6. `check:api`: ran `generate:api`, appended a marker comment to `schema.d.ts`, then ran
   `npx openapi-typescript ../contracts/openapi.yaml -o src/api/generated/schema.d.ts --check`
   against the stale file — exit 1 (`Generated types are not up-to-date!`). Restored via
   `generate:api` (never by hand) and ran the same `--check` command again — exit 0. Since the
   flag behaves correctly (non-zero stale, zero fresh), pointed `check:api` at it directly,
   deleted `scripts/check-api.js`, and updated the README paragraph. `check:api` now has no
   custom JS, so there is nothing left for `npm run lint` to need to cover.
7. Ran `generate:api` twice back-to-back and diffed the output: byte-identical.
8. Ran the full acceptance list in one pass at the end: all ten commands, all exit 0 or matching
   the required non-zero (`grep -q legacy-peer-deps .npmrc` exits 1, as required).
