## What I did

Hand-wrote every file listed above rather than running the interactive `npm create vite@latest`
scaffolder, per the task instruction to avoid a prompt that would hang the session. Installed
`react`/`react-dom` as runtime dependencies and everything else (TypeScript, Vite, the React
plugin, Tailwind v4 and its Vite plugin, Vitest, Testing Library, ESLint 10 flat config with
typescript-eslint and the React hooks/refresh plugins, Prettier, eslint-config-prettier) as
devDependencies.

TypeScript uses the project-reference split (`tsconfig.app.json` for `src/`, `tsconfig.node.json`
for `vite.config.ts`), both with `strict` and `noUncheckedIndexedAccess`, run via a single
`tsc -b --noEmit` (`typecheck` script). I verified this is not silently skipping anything by
temporarily injecting an invalid property into `vite.config.ts` and confirming `npm run
typecheck` failed with a type error pointing at that file, then reverted it.

Tailwind CSS v4 is wired through `@tailwindcss/vite` with a single `@import "tailwindcss";` in
`src/index.css` — no `tailwind.config.js`, which is the v4-recommended CSS-first approach.
Confirmed the `font-bold` utility appears in the built CSS (`dist/assets/*.css`) after `npm run
build`.

ESLint and Prettier both ignore `dist/`, `coverage/` and `src/api/generated/` (the last does not
exist yet but is pre-empted per the task brief, ready for the later openapi-typescript task).

Demonstrated the fail-before-fix rule twice, as required:
1. Changed the `App.tsx` heading text to "Schedulerz" — `npm test` failed with a clear
   Testing-Library "unable to find" error — then reverted; `npm test` passed again.
2. Added `const deliberateTypeError: number = "not a number";` inside `App` — `npm run
   typecheck` and `npm run build` both failed (exit 2) — then reverted; both passed again.

## Assumptions made

- Tailwind CSS v4's CSS-first configuration (no `tailwind.config.js`) is "the integration its
  documentation recommends for Vite" per point 4 of the task — this is the current official
  guidance for Tailwind v4 with Vite.
- ESLint flat config lint scope is `eslint .` (lints the whole project respecting `ignores` in
  `eslint.config.js`), rather than restricting to `src`, since config files (`vite.config.ts`,
  `eslint.config.js` itself) should also be lintable.
- `noUncheckedSideEffectImports` and `erasableSyntaxOnly` (newer strict-adjacent TS options)
  included in `tsconfig.app.json`/`tsconfig.node.json` since they ship in the current stable
  TypeScript and align with "strict mode on" intent; not required by the brief but low-risk.
- `docs/agent-log/` and its `INDEX.md` did not exist; created both as the logging instructions
  implied they should exist.
