## What I did

- Step 1: moved `resolveBaseUrl` unchanged into `src/api/baseUrl.ts`; `client.ts` imports it and no
  longer defines or re-exports it. `client.test.ts` was the only external importer, deleted after the
  three cases were copied verbatim to `baseUrl.test.ts`.
- Steps 2/3 (amended): the original missing-prefix idea cannot fail before the change because the
  handlers already include `/api/v1`. Per amendment 1 the test in `handlers.test.ts` instead asserts a
  request to `https://other-origin.invalid/api/v1/config` is not served, while the same path under the
  resolved base URL is. Shown red against the wildcard first (the wildcard served the cross-origin
  request, 200). `mockUrl` then makes handlers absolute; the cross-origin request is now unhandled and,
  under setup.ts's `onUnhandledRequest:"error"`, the `fetch` rejects — no real network, no
  onUnhandledRequest change, no leaked rejection (it is awaited). The `.invalid` TLD never resolves.
- Step 4: added `afterEach(cleanup)` once in `setup.ts` and removed the three per-file copies plus their
  now-unused `cleanup` imports. `cleanup.test.tsx` renders in test 1 and asserts an empty body in test 2;
  shown red before the setup change. `test.globals` untouched.
- Step 5: generated the worker with `msw init public/ --save` (records `msw.workerDirectory`), ignored it
  in ESLint and Prettier, added `browser.ts`, and `mocking.ts`. `enableMocking()` tests
  `import.meta.env.DEV` directly in the `if` before the dynamic import (amendment 3), so production
  tree-shakes the whole branch; the `"enabled"` comparison is the pure `isMockingEnabled`, unit-tested
  with plain arguments. `onUnhandledRequest` warns only for requests under the resolved base URL and
  bypasses the rest. `main.tsx` calls `enableMocking().then(render, onReject)`, logging and rendering
  anyway on failure. `dev:mock` = `vite --mode mock`; `.env.mock` holds only `VITE_API_MOCKING=enabled`.
- Step 7: the probe `const typecheckProbe: number = "x"; export {}` made `npm run typecheck` exit 2
  (TS2322 + TS6133), confirming test files are type-checked; the file was then deleted.

## Discrepancies noticed

- None blocking. Note: `resolveBaseUrl` is now duplicated in intent by `mockUrl` and `enableMocking`,
  which each resolve the base URL independently at their own module scope; this is deliberate so nothing
  under `src/mocks/` imports `client.ts` (openapi-fetch captures `globalThis.fetch` at client-create time).
